# Loot & Gear System

Loot is generated after dungeon runs and distributed to members via [[../ui/loot-distribution|Loot Distribution]]. Gear improves member stats and morale and may include trait modifier slots.

**Depends on:** [[members]], [[traits]], [[dungeon]], [[economy]]

---

## Gear Rarities

| Rarity | Colour | Description |
|---|---|---|
| **Common** | Grey | Marginal stat bumps. Vendor fodder or disenchant material. |
| **Uncommon** | Green | Solid baseline gear for mid-tier dungeons. |
| **Rare** | Blue | Noticeable power spike. May include a minor trait bonus. |
| **Epic** | Purple | Significant stat bonuses. One guaranteed trait mod slot. |
| **Legendary** | Orange | Best-in-slot potential. Two trait slots; unique visual; may unlock a special dungeon. |
| **Prestige** | Red/Gold | Post-endgame. Crafted via special materials. Grants guild-wide passive buffs. |

## Loot Distribution

After each run, generated loot enters the Guild Stash. The player assigns items via [[../ui/loot-distribution|Loot Distribution]].

- **Manual** — select an item, select a member, confirm.
- **Auto-Loot Rules** — pre-set priority lists per member. Configurable per run.
- **Loot Goblin Claim** — members with the Loot Goblin [[traits|trait]] may claim items before distribution. Player can allow or override each claim.
- **Morale Impact** — under-geared members lose morale over time; well-geared members gain loyalty.

> [!note] Future System — Unclaimed Loot
> Items not assigned after a run time-out will flow into a guild stash reserve. Deferred — current behaviour requires manual assignment. See [[../roadmap]].

## Loot Generation

Drop tables are defined per dungeon in `dungeons.ron`. Generated by a system reading room result events.

- **Active run bonus** — runs with the player character present receive +10–25% loot quality, scaling with difficulty.
- **Flawless Clear bonus** — zero QTE misses adds additional rare+ items. See [[qte#Flawless Clear]].

## Implementation Notes

### Bevy

Gear slots are a component on member entities. Loot generation writes items to `Res<GuildStash>`. Equipping an item fires a `LootAssigned` event consumed by a system that updates the gear slot component and adjusts morale and loyalty values.

Loot Goblin claim detection happens inside the generation system — it checks `TraitSet` components of party members after each item rolls and writes a `GoblinClaimed` event for the UI to present. Player resolution writes either `GoblinClaimAllowed` or `GoblinClaimOverridden`, consumed by the stash system.

### Flutter + Flame
`GuildStash` is a field on `GuildCubit` state — a `List<ItemInstance>`. Loot generation is a pure Dart function called by `GameBloc` on `RunCompleted` events, using `ItemDefinition` data from `DataRepository`.

Goblin claim detection happens inside the loot generation function — it checks `TraitSet` on party member models and returns a list of `GoblinClaim` objects alongside the generated loot. `GameBloc` stores pending claims in `CombatState`. The [[../ui/loot-distribution|Loot Distribution]] screen reads these from state and presents the allow/override dialog via a Flutter `AlertDialog`.

Gear equipping calls `GuildCubit.equipItem()`, which updates the `Member` model's gear slot field using `copyWith` and recalculates derived stats. Morale and loyalty adjustments are applied in the same method.
